# 実験結果作成

Kaggle実験について、実行結果を確認し、再現可能な提出記録を作成または更新する。

## 適用範囲

- 正式提出に対応する `submissions/<連番>-v<Kaggle版番号>-<実験名>/README.md` の作成・更新
- `submissions/README.md` の提出一覧の更新
- 実験設定、実行結果、検証結果、公開スコア、既知の制約、次の改善案の整理

単なるコード実装、実験案の検討、または提出を伴わない小さな検証だけには使わない。

## 進め方

1. リポジトリの `AGENTS.md`、`submissions/TEMPLATE.md`、`submissions/README.md` を読み、既存記録の書式と連番を確認する。
2. 実行に使った版、設定、データ選択、前処理、モデル、学習・検証結果、推論方法、提出識別子、採点状況を、ログ・成果物・設定ファイルから確認する。不明な値は推測せず「未記入」または「確認中」と明記する。
3. 正式提出ならテンプレートを基に日本語で記録を作成する。コードと設定の実際の挙動を記し、後から同じ実験をたどれる内容にする。
4. 提出記録を追加・更新したら、提出一覧にも連番、Kaggle版、日時、概要、公開スコア、状態を同期して記載する。
5. 記録対象の変更がある場合は `./scripts/verify.sh` を実行し、結果を報告する。Python環境が必要なら必ず `uv` を使用する。

## 境界と注意点

- Kaggleの実行、正式提出、外部へのプッシュ、コミットは、ユーザーが明示した場合だけ実行する。必要な認証や競技規約の受諾も確認する。
- 失敗したKaggle実行は正式提出の連番に含めない。ただし重要な知見は該当提出の「実行・提出基盤」に残す。
- 競技データ、認証情報、検査画像、生成物のうち追跡対象外のものを記録やコミットに含めない。
- スコアが未確定なら確定値のように扱わず、採点待ち・未公開など状態を明記する。
